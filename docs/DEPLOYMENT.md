# Submission deployment

This package deploys the standalone synthetic MVP, not the full CARE host. CARE integration remains independently verified in `../care-sandbox`. Use synthetic data only.

## Render setup

1. Create a Render account and a GitHub repository containing **only this second-brain directory**. Do not publish the parent csb workspace or local runtime files. The directory currently inherits an unrelated ancestor Git repository; create a dedicated repository before publishing. No repository has been created or pushed by this task.
2. Create a Render Blueprint from that repository using `render.yaml`. It requests a paid Starter service and a persistent disk; review the current price in the dashboard before purchasing. A free ephemeral filesystem is unsuitable for this SQLite demo.
3. Supply `SECOND_BRAIN_KEY` with a Fernet key generated locally using `.venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Enter it only in the hosting secret field. Preserve this key for every redeploy.
4. Supply `DJANGO_ALLOWED_HOSTS` with the actual assigned hostname (no scheme or path), e.g. `clinician-second-brain-xxxx.onrender.com`. Update it if Render assigns another hostname. `DJANGO_SECRET_KEY` is generated by the Blueprint.
5. Deploy. Startup migrates the persistent SQLite database and seeds one synthetic case idempotently. In Render Shell read `/var/data/demo-login.txt` for the randomly generated clinician password. Share that demo password in the evaluator access field, never an API key or encryption key.
6. Test the public HTTPS URL in an incognito browser. Log in, inspect history, upload the synthetic image and scanned PDF, correct OCR, review a source, confirm facts, generate/review/approve/export a document. Check citations and verify editing revokes approval. Restart the service and confirm records and login survive.

The container serves the React build and API from the same origin through Gunicorn. SQLite and demo credentials live on the persistent disk. Use one service instance; this configuration is for a low-traffic hackathon demo. Keep encryption keys in host secrets. Optional Sarvam is omitted unless an API key with credits is configured.

## Local container verification

Build: `docker build -t second-brain-submission:local .`

Run on loopback with an isolated named volume:

```sh
docker run --rm --name second-brain-submission -p 127.0.0.1:18000:8000 -v second-brain-submission-data:/var/data second-brain-submission:local
```

The default local mode accepts localhost and uses disk-backed generated keys. Hosted mode requires explicit secrets, hostname, and a trusted HTTPS proxy. Never expose the local-mode container directly to the internet.

## Full CARE deployment

The Render Blueprint does not include CARE. A full integrated demo needs a separately provisioned CARE server, PostgreSQL, Redis and object storage, plus the built CARE host and plugin frontend. Install the backend plugin and register it externally via `ADDITIONAL_PLUGS`; configure `REACT_ENABLED_APPS` with the HTTPS plugin remote. Use the pinned revisions and permission checks documented in the CARE sandbox. Generate fresh demo credentials rather than exposing the local sandbox password. Never upload `.agent/plugin-secrets.env`, local databases or runtime directories.
